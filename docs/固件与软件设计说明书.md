# CH32L103 USB→CAN 固件与软件设计说明书（驱动 DM-J4310-2EC）
> 配套工程：`../04_工程/CH32L103_USB2CAN_DM/`（可编译，已产出 .hex/.bin）
> 上位机例程：`../03_主机例程/dm_j4310_usbcan.py`
> 硬件参考：`../01_硬件/硬件连接与原理图设计.md`

## 1 总体架构

```
 PC(CDC COMx)
    │  上行 AA|…13B   下行 55|…13B
    ▼                     ▼
 USBFS 全速设备           USBFS 全速设备
  EP3 IN(CDC数据)         EP2 OUT(CDC数据)
    │                       │
    ▼                       ▼
 16帧 CAN RX FIFO(ISR)   2048B 字节环(主循环)
    ▲                       │ 13B帧解析器
    │ CAN1 RX0 中断         ▼
  CAN1 @1Mbps ←——→ CAN1 TX(3邮箱阻塞发送)
    │ TXD=PB9 RXD=PB8
    ▼
 SIT1051T/3 → CANH/CANL → DM-J4310-2EC @1Mbps
```

- 数据通路（主循环 `Link_Poll()` 依次执行）：
  1. USB OUT 段 → `s_ring` 字节环；
  2. `s_ring` → 13B 帧解析器 → CAN1 发送（阻塞等邮箱，天然按总线速率节流）；
  3. CAN RX 中断推入 16 深帧 FIFO，主循环取出打包成 13B 帧放入 CDC 上行环；
  4. CDC 上行环 → EP3 IN，满 64B 立即发、不足 64B 等 0.2ms 短超时打包发，
     恰好 64B 整倍数流末尾自动补 0 长度包（CDC 语义需要）。
- 反向背压：USB 下行由 14×64B 段缓冲 + NAK 流控；上行环满则丢帧计数并闪错误 LED，
  不会死锁。

## 2 时钟与关键外设配置

### 2.1 时钟（`system_ch32l103.c`）
- `SYSCLK_FREQ_96MHz_HSI`：HSI 经 PLL×12 = **96MHz**；
  - HCLK=96MHz，PCLK2(APB2)=96MHz，PCLK1(APB1)=**48MHz**；
  - USB 时钟 = PLL/2 = **48MHz**（全速要求），无需外部晶振；
  - CAN1 挂在 APB1，取 PCLK1=48MHz 作时基。

### 2.2 CAN1（`can_bsp.c`）@1Mbps
- **重映射**：`AFIO_PCFR1[14:13]=10b` → `CAN1_RX=PB8`、`CAN1_TX=PB9`
  （默认 00b 是 PA11/PA12，与 USB 冲突，必须改；直接写寄存器最稳妥）。
- GPIO：PB9 = 复用推挽 50MHz；PB8 = 上拉输入。
- 位定时（**PCLK1=48MHz**）：
  `tq 时钟 = 48MHz / Prescaler(2) = 24MHz`；
  `1bit = 1(SYNC) + 15(BS1) + 8(BS2) = 24tq = 1µs → 1.000Mbps`。
- 其余：Normal 模式、`SJW=1tq`、ABOM=ENABLE（自动退出 Bus-Off）、
  `NART=DISABLE`（仲裁失败自动重发）、`TXFP=ENABLE`（按请求顺序发送）、FIFO0 满中断。
- 接收中断向量：**`USB_LP_CAN1_RX0_IRQHandler`**（启动文件固定名），每次把 FIFO0
  全部读空并转交桥层，RTR/标准帧/扩展帧(DLC>8 截断、扩展帧丢弃计数)。
- 发送：`CAN1_SendStdBlock()` 等待空闲邮箱→加载→等发送完成，带超时保护；
  CAN 波特率决定其不会“忙等”太长（1Mbps 一帧 ≈ 130µs 内）。

### 2.3 USB CDC（EVT SimulateCDC 改造）
- USBFS 全速设备；描述符：
  - `VID/PID = 1A86 / FE0C`（WCH 默认，可改），产品名 `L103 USB-CAN 1M`；
  - 接口0：CDC ACM（含通知端点 **EP1 IN 0x81** 中断）；接口1：数据（**EP2 OUT 0x02**、**EP3 IN 0x83**，批量，64B）；
  - 驱动：Windows 免驱识别为“USB 串行设备(COMx)”，Linux/macOS 为 /dev/ttyACMx。
- EP2 OUT 数据直接 DMA 进 `UART2_Tx_Buf`（1024B/16 段）；EP3 IN 上传 64B 段。
- **重要**：`USBFS_UC_DEV_PU_EN` 打开芯片内部 1.5kΩ D+ 上拉 → 板上无需外置上拉。

### 2.4 定时器 TIM2（100µs 心跳）
- `TIM2_Init`：Prescaler=SYSCLK/1MHz-1，Period=100-1 → **100µs 中断**；
- 中断里：`Uart.Rx_TimeOut++`（上行短包尾超时）、`Uart.USB_Up_TimeOut++`、
  `Link_Tick100us()`（PA15 心跳 0.5s、PB4 错误脉冲 20ms、EXT_IO_Tick100us 调度、0.5s 统计打印）。

### 2.5 调试打印
- USART1（PA9 TX，115200 8N1，可选接）：
  `tx=… rx=… hb=… drop=… bad=…`（`#define LINK_DEBUG_STATS 1` 关闭可省 printf）。
- 若不用 USART1，可不接；不影响 USB-CAN 功能。

## 3 链路协议（固件 `usb2can_link.h/c`，PC 端同款实现）

固定 **13 字节**（标准帧 11bit）：

| 字节 | 下行 PC→桥 | 上行 桥→PC |
|------|-----------|-----------|
| 0 | `0x55` | `0xAA` |
| 1 | flg | flg |
| 2 | CAN ID 低 8 位 | 同左 |
| 3 | CAN ID 高 3 位(0~7) | 同左 |
| 4..11 | DLC 个数据字节(不足补0) | 同左 |
| 12 | xor 校验 | 同左 |

- `flg`：bit7=RTR；bit3..0=DLC(0..8)；bit6 预留（本桥不发扩展帧，收到扩展帧丢弃+计数）。
- `xor = byte1 ^ byte2 ^ … ^ byte11`。
- 校验错/同步丢失：解析器自动重新同步（找 0x55/0xAA），错帧计数并闪 PB4。

例：向 ID=0x101 发位置速度命令（目标 1.0rad、限速 0.5rad/s）：
```
DLC=8  data = 00 00 80 3F 00 00 00 3F   (1.0f LE, 0.5f LE)
55 | 08 | 01 01 | 00 00 80 3F 00 00 00 3F | xor
```
> 主机例程里 `pack_down()` / `Bridge._frames()` 已实现打包/拆包，无需手写。

## 4 驱动 DM-J4310-2EC 的帧格式（手册 V1.2 + 协议 V1.4 核对）

### 4.1 帧 ID 与匹配
- 电机默认 CAN **1Mbps、STD 11bit**；匹配规则：**命令帧 ID 低 8 位**与 ESC_ID(reg 0x08) 比较；
- 命令 ID：MIT=`ESC_ID`；位置速度=`0x100+ESC`；速度=`0x200+ESC`；力位混控=`0x300+ESC`；
- **反馈帧 ID = MST_ID（reg 0x07，出厂默认 0）**，每条匹配命令回一帧。

### 4.2 使能/失能等（所有模式 ID 按 4.1）
| 操作 | 数据(8B) |
|------|----------|
| 使能 | `FF FF FF FF FF FF FF FC` |
| 失能 | `FF FF FF FF FF FF FF FD` |
| 清错 | `FF FF FF FF FF FF FF FB` |
| 存零点 | `FF FF FF FF FF FF FF FE` |

### 4.3 寄存器读写（帧 ID=0x7FF）
| 操作 | D0 | D1 | D2 | D3 | D4..D7 |
|------|----|----|----|----|--------|
| 读 | CANID_L | CANID_H | `0x33` | RID | 0 |
| 写 | CANID_L | CANID_H | `0x55` | RID | 值(4B LE float/u32) |
| 存Flash | CANID_L | CANID_H | `0xAA` | 0x01 | 0 |
- 回帧：ID=MST_ID，D0..D3 同请求（0x33/0x55/0xAA 原样回），写后回写的数据。
- 常用寄存器：
  `0x07 MST_ID`、`0x08 ESC_ID`（u32）；`0x0A CTRL_MODE`(1=MIT,2=位置速度,3=速度,4=力位混控,u32)；
  `0x0E 固件版本`、`0x0F 子版本`(u32)；`0x15 PMAX`、`0x16 VMAX`、`0x17 TMAX`(float)；
  `0x50 p_m`、`0x51 xout`(float, rad)；`0x23 波特率`(4=1M)。
- ⚠ `0x23` 写 >1M 会让电机进 **CAN FD**，普通 CAN 将收不到反馈 → 真机确认 1M(4) 再操作。

### 4.4 运动命令
| 模式 | ID | 数据 |
|------|----|------|
| 位置速度(2) | `0x100+ESC` | `p_des`(float LE) + `v_des`(float LE, 限速 rad/s) = 8B |
| 速度(3) | `0x200+ESC` | `v_des`(float LE) = 4B |
| 力位混控(4) | `0x300+ESC` | `p_des`(f32) + `v_des`(u16×100) + `i_des`(u16×10000) = 8B |
| MIT(1) | `ESC` | 5 参数按位打包 8B，见 §4.6 |

### 4.5 反馈帧（ID=MST_ID，8B，各模式相同）
| D0 | D1 | D2 | D3 | D4 | D5 | D6 | D7 |
|----|----|----|----|----|----|----|----|
| ID\|ERR<<4 | POS[15:8] | POS[7:0] | VEL[11:4] | VEL[3:0]\|T[11:8] | T[7:0] | T_MOS℃ | T_Rotor℃ |
- 位置 16bit、速度/扭矩 12bit，均为“无符号等比例”编码（0..2^n-1 ↔ −MAX..+MAX）；
  解算即 `uint_to_float(x, -MAX, +MAX, bits)`（手册 V1.4 同款）：
  `val = x/65535 × 2·PMAX − PMAX`（16bit），12bit 用 4095。
- ERR：0失能 / 1使能 / 8超压 / 9欠压 / A过流 / B MOS过温 / C 线圈过温 / D 通讯丢失 / E 过载。
- ID = 反馈字节 D0 低 4 位（CAN ID 低 8 位，常规建议 ESC<16 以免与 ERR 冲突）。

### 4.6 MIT 位打包（若要用，按协议 V1.4 C 代码）
```
pos16: D0=pos>>8, D1=pos
vel12: D2=vel>>4, D3=((vel&0xF)<<4)|(kp>>8)
kp12 : D4=kp
kd12 : D5=kd>>4, D6=((kd&0xF)<<4)|(tor>>8)
tor12: D7=tor
raw = float_to_uint(x, -MAX, +MAX, bits)  // (int)((x+MAX)*(2^bits-1)/(2*MAX))
```
KP∈[0,500]，KD∈[0,5]。MIT 模式位置回路 **kd 不能为 0**。主机脚本未内置 MIT 打包，
如需请在脚本内仿照 `ctrl_motor()` 增加命令。

## 5 主机例程（`../03_主机例程/dm_j4310_usbcan.py`）
依赖：`pip install pyserial`。全部子命令：
```
probe                     # 扫 ESC_ID 0..15 并读版本/位置(找到第一个即停)
status                    # 读模式/PMAX/VMAX/TMAX/p_m/xout
set_mode 2                # 1 MIT / 2 位置速度 / 3 速度 / 4 力位混控
enable / disable          # 使能/失能(失能=默认红灯)
clear                     # 清故障
zero                      # 存当前位置为零点
read  0x51                # 读寄存器(float 或 u32 自动识别)
write 0x15 12.5 --fmt f   # 写寄存器(立即生效, 掉电丢失; 失能后可用 store)
store                     # 暂未做 CLI, 在脚本里 store()
move  1.0 0.5             # 位置速度: 到1.0rad, 限速0.5rad/s
vel   2.0                 # 速度模式: 2.0 rad/s
```
- 默认 `ESC_ID=1、MST_ID=0`；真机请先 `probe`（或达妙调试助手）确认，可用 `--esc` 覆盖。
- `status/move` 会先自动读 0x0A、0x15~0x17 刷新模式与量程，无需手动填 PMAX。
- ⚠ 达妙实机经验：部分固件对“速度模式(3)”支持不稳，**推荐先用位置速度模式(2)**。
- 样例命令（安全起见先低速）：
  ```
  python dm_j4310_usbcan.py COM5 probe
  python dm_j4310_usbcan.py COM5 set_mode 2
  python dm_j4310_usbcan.py COM5 enable
  python dm_j4310_usbcan.py COM5 move 0.0 0.2     # 走到零点, 限速0.2rad/s
  python dm_j4310_usbcan.py COM5 move 1.0 0.5
  python dm_j4310_usbcan.py COM5 disable
  ```

## 6 工程与烧录
- 工程根目录 `make` 即可；`make flash` 需 **WCH-Link**（SWDIO/SWCLK/3V3/GND 四线，
  K8U6 无 NRST）。
- 也可以用 MounRiver Studio 打开工程后“下载”；或用 OpenOCD `wch-riscv.cfg`。
- 编译结果（含扩展模块）：FLASH≈17.1KB(26.3%)，RAM≈7.8KB(38.8%)，余量充足；退回最小桥约 15.9KB/7.6KB。
- 直接把 `User/can_bsp.*`、`User/usb2can_link.*`、`User/ch32l103_it.c` 中改动合并到你已有
  的 SimulateCDC 工程也行（注意保留 `debug.c` 的 newlib stub，见工程 README）。

## 7 常见问题排查
| 现象 | 处理 |
|------|------|
| 不识别 COM | USB D+/D− 接反/虚焊；板先上电再插线；PA11/PA12 未被 CAN 抢(重映射已做) |
| probe 无反应 | 电机是否 24V 供电；ESC/MST 与默认不同；波特率不是 1M(被改 >1M 进 FD) |
| enable 后红灯/ERR | 先 `clear`；确认控制模式 reg0x0A；CANH/CANL 是否接反 |
| 电机发抖/过冲 | move 限速调小；不要改极对数/减速比；首次调试脱开负载 |
| 反馈偶尔丢 | 短线合上 120Ω(JP1)；收发器 3.3V 供电；串阻过大(>33Ω)会降幅 |
| 板子 CAN 一直报错 | Bus-Off/无终端/两节点阻抗不匹配；看 `tx=/rx=` 统计与红灯闪烁 |

## 8 扩展功能软件设计（ext_io 模块，可选）
> 配套硬件：《01_硬件/扩展功能与全IO分配.md》。代码：`User/ext_io.h` / `ext_io.c`，
> 已并入 Makefile 并编译通过（本桥加扩展后 FLASH≈17.1KB=26.3%，RAM≈7.8KB=38.8%）。

### 8.1 新增/调整的引脚
| 引脚 | 原用途 | 现用途 |
|------|--------|--------|
| PB5 | 错误 LED（可选） | **WS2812 DATA**（错误 LED 移到 PB4） |
| PB4 | — | 错误 LED（可选） |
| PB6/PB7 | — | TIM4_CH1/CH2 舵机 PWM（50Hz，0.5~2.5ms） |
| PA0/PA1/PA4 | — | ADC0/1/4 ← 三只 10kΩ 电位器 |
| PA5 | — | ADC5 ← 电池电压分压 |
| PA2/PA3 | USART2 预留 | 不变：USART2_TX/RX 预留（本模块不初始化） |
| PA9/PA10 | USART1 Debug | 不变：调试打印口 |

### 8.2 API
- `EXT_IO_Init()`：使能 ADC1/GPIO/TIM4 时钟，PA0/1/4/5 配 AIN，
  PB5 配推挽输出（WS2812 空闲低），PB6/PB7 配 AF_PP 并启动 TIM4 双路 PWM，
  默认 1500us 中位（防止舵机上电猛跳）。
- `EXT_IO_Tick100us()`：由 `ch32l103_it.c` 的 TIM2 中断调用，驱动 10ms 调度。
- `EXT_IO_Poll()`：main 循环里每次迭代调用；约每 10ms 采 4 路 ADC（每路各采 2 次
  求平均），单次转换约 2µs，短阻塞不影响 USB/CAN。读值：
  - `EXT_ADC_GetRaw(idx)` 0..4095；
  - `EXT_ADC_GetVolt(idx)` 0..3.3V；
  - `EXT_VBat_GetVolt()` = ADC5 电压 × `EXT_VBAT_DIVIDER`(默认11)。
- `EXT_Servo_SetUs(ch, us)`：ch=0→PB6，ch=1→PB7；限幅 500..2500us。
- `EXT_WS2812_WriteByte / Reset / SendGRB(grb,n)`：位带发送，内部关中断。
  **n 颗灯珠 ≈ n×31µs+80µs**（8 颗≈0.33ms/16 颗≈0.58ms）；默认 main 不主动调用，
  需在应用处低频刷新，见 §8.3 时序标定说明。

### 8.3 WS2812 时序与 CAN 实时性
- 本模块按 96MHz 主频粗估时序常量（`ext_io.c` 顶部 `W_T0H_LOOPS` 等 4 个宏）。
  **首次上板务必用示波器/逻辑分析仪抓 PB5 校准时序**：T0H≈0.4µs、T1H≈0.85µs、
  周期≈1.25µs、帧间低电平 ≥50µs。
- 发送期间关中断；若你的应用在 1M 总线上高频收发运动帧，建议灯珠 ≤8 颗并低频刷新；
  更严格场合把 WS2812 改到 PA8(TIM1_CH1)，用定时器+DMA 方案（本文档仅给接口预留）。

### 8.4 若要“退回最小 USB→CAN 桥”
删掉/注释 `main.c` 的 `EXT_IO_Init()`、`EXT_IO_Poll()`，`ch32l103_it.c` 的
`EXT_IO_Tick100us()`，Makefile 的 `ext_io.c` 即可；其余（CAN/USB/协议）不受影响。
