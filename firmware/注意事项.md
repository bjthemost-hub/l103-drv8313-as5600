## 电机参数（极对数 / 堵转阈值 / 母线电压）现在存在 Flash 里

`board.h` 里的 `MOTOR_POLE_PAIRS` / `MOTOR_STALL_AMP` 现在只是**编译默认值**（14 极对 / 2.0 A）。
真正生效的是 Flash 里那一条记录（`pos_log`，**32 B**，magic **`LP31`**，在 `0x0800FC00~0x0800FFFF`）。
母线电压的编译默认值是 `MOTOR_VOLTAGE_SUPPLY`（24.0 V）。

**换电机操作顺序**（比如这次新电机是 11 极对）：

1. 先失能：串口 `D`（或 CAN `0x110` b0=0）—— 使能中改极对数会被拒
2. `#11` 设极对数，`#11,2.5` 连阈值一起设，`#0,2.5` 只设阈值，`#0,0,36` 只设母线电压；`#` 单独敲是查看
3. **必须重跑 `A` 重新对齐** —— 改极对数会清掉 `aligned`
4. 对齐日志里核对：`MOT: PP check: configured=11 estimated=11 OK`（只核对，不自动采纳）

CAN 侧等价命令是 `0x116`（b3 bit0 必须写 1 才是"确认要改"），应答新增 `0x184` 电机参数帧（b4..5 = 母线电压 [0.01 V]）。
详见板卡根目录的 `CAN命令清单_2026-09-19.md`。

**⚠ 注意：`make flash` 会把整片 64 KB Flash 擦掉，这条记录一定没（2026-09-28 受控实测）。**

- 机制：`make flash` = `openocd -c "init" -c "halt" -c "program <elf> verify reset"`。
  WCH 的 OpenOCD 驱动做的是**整片擦**，不是只擦镜像占用的扇区 ——
  镜像只到 `code_end=0x0000B620`，而日志页在 `0x0800FC00~0x0800FFFF`（1 KB 的最后一页），照样被清掉。
- 受控对照（同一天、**同一个 ELF**）：烧写后开机横幅回到编译默认 `pole_pairs=14 VM=24.0V`；
  只 `-c "init" -c "reset" -c "exit"`（不 program）时横幅仍是 Flash 里的 `pole_pairs=11 VM=13.0V`。
  → 擦除是 `program` 造成的，固件自己的 Flash 写入（`pos_log`）是好的。
- 所以每次烧写完都要：**重设参数 + 重跑 `A`**（对齐结果也在同一条记录里，本来就要重跑）。
  一键脚本按需自备（流程如上）。
  —— 烧完自动 `D` → `#11,2.00,13` → `A` → `#` → `E`，参数可改 `-Pp/-Amp/-Vbus`。
- 页粒度：固件按 **256 B 一页**（依据 `ch32l103_flash.c` 里 `FLASH_ErasePage_Fast` 的官方注释），
  4 页 = 1 KB；OpenOCD 那边报的"1 KB 扇区 × 64"是它自己的模型，两者不冲突。

**烧完之后怎么把参数补回来（2026-09-29 实测）** —— 不用串口，CAN 就能做：

- 先 `0x110` b0=0 **失能**。使能中改极对数会被 `motion_pv.c:528` 直接拒，
  而且**只在 `0x183` 的 latch 上留一个 `CMD_REJECT`**，没有别的提示，很容易以为"发成功了"。
  （上电默认就是使能态：`foc_motor.c:98` 的 `Motor_Init()` 里有 `DRV8313_Enable()`；
  Uq=0，所以轴不动、不发热。）
- 再 `0x116`：`b0`=极对数, `b1..2`=堵转阈值[0.01 A], `b3`bit0=1(确认位), `b4..5`=母线电压[0.01 V]。
  例：`0b c8 00 01 60 09 00 00` = 11 极对 / 2.00 A / 24.00 V。
  回 `0x184`，格式 `b0`=极对, `b1..2`=阈值, `b3` bit0 来自 Flash / bit1 已对齐 / bit2 已使能,
  `b4..5`=母线电压。用 `0x113 b0=0xFF` 可以一次把 0x181/0x182/0x183/0x184 四帧全要回来核对。
- 参数补完仍要 **`A` 重新对齐**（`A` 只有串口有，CAN 没有对齐命令），再重设机械零点（`0x112`）。

**用 OpenOCD 命令行烧写时的路径坑（2026-09-29 踩到）**：`-c` 后面的字符串走 Tcl 解析，
Windows 反斜杠会被吃掉 —— `-c "dump_image E:\work\....bin 0 0x10000"`
里的 `\2026` 会被当八进制转义，报 `couldn't open E:Codex...`（反斜杠全没了）。
用**正斜杠**并加 `{}` 包住路径：`-c "dump_image {E:/work/.../a.bin} 0 0x10000"`。

## 运行期行为（2026-09-28 定，都是实测）

### 上电默认相电压上限 = vbus/sqrt(3)

`board.h` 的 `MOTOR_VOLTAGE_LIMIT` 现在是 **`0.0f`，它是"跟母线走"的哨兵值，不是"限幅 0V"**。
真正生效的限幅由 `Motion_ApplyBootVoltageLimit()` 按 Flash 里的 vbus 算：
**13V → 7.51V，24V → 13.86V，36V → 20.78V**（`vbus/_SQRT3`）。
运行期 `L<volts>` 仍可往下压，断电失效。

⚠ 2026-09-28 踩过（`A` 对齐失败的真正根因）：把 `MOTOR_VOLTAGE_LIMIT` 改成 0 时，
`foc_motor.c:Motor_Init()` 里那句

```c
if(voltage_sensor_align > voltage_limit) voltage_sensor_align = voltage_limit;
```

会在这个空窗期把 `voltage_sensor_align`（2.5V）**钳成 0V** —— 因为
`Motion_ApplyBootVoltageLimit()` 要等 Flash 参数恢复完才跑，在 `Motor_Init()` 之后。
后果：`A` 扫场加 0V、转子一动不动 → `Failed to notice movement`，
而失败路径又调 `DRV8313_Disable()`，于是 `A` 再也成功不了（死锁）。
现在有两道防线：`main.c` 给 `voltage_limit` 的初值改成 `vbus/_SQRT3`，
`foc_motor.c` 那句钳位加了 `voltage_limit > 0.0f &&` 前提。**动这里的人别把任一道删掉。**

### 控制模式切换（`M0..M4`）会丢掉上一条 PV 轨迹

`'M'` 现在先 `Motion_AbortPV()`（把 `mode` 清成 `PV_IDLE`）；
要进角度环（`M2`）时再 `Motion_SyncAngleTarget()` —— **原地保持，不跳**。两个实测坑：

- **位置轨迹没跑完就 `M1` + `V10`**：`mode` 还停在 `PV_POS`，`Motion_Task` 每拍
  `cmd_target = ref_rad;`，把刚下的 1.047 rad/s 冲成 0 → 速度环看着"没反应"。
- **速度模式 `V0` 之后 `M2`**：`mode` 还停在 `PV_VEL`，`cmd_target = vlim_rad;` 会把
  轨迹的**速度上限 (rad/s) 当成绝对位置 (rad)** 塞给角度环 → 轴自己跑过去。

### `Y` 的传感器诊断多打一行

`AS5600: ANGLE(0x0E)=<n> CONF(0x07)=0xXXXX`（只读）。用途：区分
"芯片内部角输出停了" 和 "配置被改成低功耗/非磁角度输出"。

⚠ **`raw` 读数是 0（或 4095）附近不等于传感器坏。** AS5600 的 12 位角在
`4095 ↔ 0` 处是过零点；关节正好停在那一带时 `raw` 会稳定显示个位数。
2026-09-28 实测：`raw` 卡在 0 长达 6 分钟，一度判成"读数卡死"，
事后走一圈 `raw 37 → 3072 → 1024 → 0`（中间穿 4095/0）与固件 `+0.25 / −0.5 / +0.25` 圈
**逐段严格对上**，`MAG` 也一直在动 → 传感器是好的，关节就是停在 `Z` 定义零点的那个位置。
判活办法：`Y` 看 `MAG` 有没有在动，或让它转一点看 `raw` 变不变。

## 固件"瘦身"后的规矩（2026-09-28）

原本 Flash 占用 **98.05%**（只剩 1260 B）。**修好中断向量表之后重测（2026-09-28，不带 `-flto`）**：
`FLASH 46560 B / 63 KB = 72.17%`、`RAM 5452 B / 20 KB = 26.62%`。
（中间一度看到过 64.58% —— 那是开着 `-flto` 的镜像，**中断代码根本没链进去**，是个偏低好几 KB 的假数，别再引用。）
省下来这些东西有个共同点：**都是"调一次就把整个库拖进来"的**。所以下面这些**别再随手写**：

| 别写 | 为什么要多花空间 | 这个工程里该写什么 |
|---|---|---|
| `atof()` / `strtod()` | 一次带走 strtod 全家 + 多精度(`mprec`) + `gdtoa` + 双精度软浮点 + `malloc`，实测家族合计 **18723 B** | `Cmd_ParseFloat()`（在 `User\cmd.c`，`User\cmd.h` 有原型） |
| 浮点常数不带 `f`（`0.5`、`3.14159`） | `float` 表达式里混进一个 `double` 就**整条升级成双精度**，拉进 `__adddf3/__subdf3/__fixdfsi`。`_round()` 里那个 `0.5` 实测值 **3892 B** | 一律 `0.5f` / `3.14159f`；变量一律 `float` |
| `sqrtf()` | newlib 的 `sqrtf` 内部就是 `(float)sqrt((double)x)`，拉进 `__divdf3(1460) + __truncdfsf2(362) + __extendsfdf2`，实测 **2484 B** | `SqrtF()`（在 `User\foc_utils.c`） |
| `printf()` / `vsnprintf()` | 一次就把 stdio 全家（vfprintf / svfprintf / fvwrite / findfp / smakebuf / wsetup / fflush / …）连 `malloc` 一起拖进来，实测 **4796 B Flash + 116 B RAM** | **照旧写 `printf(...)` 即可** —— `User\mini_fmt.h` 已经把它 `#define` 成 `mini_printf`；要写进缓冲用 `mini_snprintf` / `mini_vsnprintf` |
| 中文输出字符串 | 实测 39 条字符串 / 333 个汉字，全换成英文**只省 12 B** | **不用改**（反向经验：别为了省 Flash 动文案；注释里的汉字根本不进制） |

要点：

- `mini_printf` 支持 `%d %i %u %x %X %c %s %%` + 标志 `- 0 + 空格` + 宽度 + 长度 `l`。
  **不支持浮点** `%f/%e/%g`（这板子没 FPU）—— 浮点先用 `FmtF(v, dec)` / `FmtFS(v, dec)` 转成字符串再 `%s`。
- **加了新的 `.c` 文件必须写进 `Makefile` 的 `C_SOURCES`**（那是手写清单）。
  MounRiver 那边不用动：`.cproject` 的 `<sourceEntries>` 是工程根，新文件自动发现
  （但"同工程另一个 main"那种必须进 `excluding`，否则链接报 `multiple definition`）。
- 栈只有 **2048 B**（`SRC/Ld/Link.ld` 的 `__stack_size`）：`mini_fmt.c` 内部按 64 B 分块往 UART 塞，
  别把 `MINI_CHUNK` 调大（`cprintf` 自己已经占 384 B）。
- 这些都是**编译期**省空间，改完必须重编才生效。量占用只看链接末尾那行
  `FLASH: xxxxx B / 63 KB (xx%)`（`Makefile` 已带 `-Wl,--print-memory-usage`），**别用 `size` 的 total、
  也别看 `.bin` 大小**（混了 debug 段）。
- 详细过程与每一刀的实测数字见工程根的
  开源版未附带当时的实验记录；核心做法是把 double 换成 float、去掉 stdio。
- 姊妹工程 `04_工程\CH32L103_DRV8313_FOC`（无 CAN 旧版）**没同步这些改动**，它还是 `atof` + `0.5`。

## 出问题时先看哪

- **绿灯不闪 / 串口一个字节都没有**：先确认 `Makefile` 的 `CFLAGS`/`LDFLAGS` 和 MRS 生成的
  `obj/makefile` / `obj/*/subdir.mk` 里**没有 `-flto`**（见上面「坑」第 1 条），
  再用 `riscv-none-embed-nm` 看 `USART1_IRQHandler` 是 `T` 还是 `W` —— 是 `W` 就说明中断没链上。

- 串口 115200，上电会打 `MOTCFG: from flash / compiled default pole_pairs=… stall=… A vbus=… V`
- 位置日志状态：串口 `W`
- 故障现场：串口 `I`
- `WCH-Link failed to connect with riscvchip` 这条通用报错**通常不是工具问题**，先按
  "量 3V3 → 通断 SWDIO/SWCLK → 补焊 QFN 的散热焊盘 EP" 的顺序查（EP 是唯一的地，虚焊会各轨正常但不工作）。
  OpenOCD 的 `Error: Unsupported register (enum gdb_regno)(8)` 无害，以 `Verified OK` 为准。

- **上位机脚本 `l103_can.py` 收不到数据 / `swing`·`seq` 报"全部未到位 / 峰值 0.0 rpm"**：
  看 `..\05_工具与日志\注意事项_上位机脚本.md`。
  一句话：固件 debug 关掉后板子**是被动设备**，上位机必须主动发 `0x113`(b0=0) 换 `0x181`
  （布局与 `0x180` 相同），光监听永远收不到；另外上位机串口读法必须非阻塞，
  否则每次 `ReadFile` 白等 50 ms，10 ms 轮询会被拖成 18 Hz（2026-09-29 实测）。
