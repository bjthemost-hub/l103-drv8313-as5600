# 注意事项 · 2026-10-06 烧写本板会整片擦 Flash（写固件前必读）

适用：`CH32L103 + DRV8313 FOC CAN` 台架板，本机 MounRiver 自带的 WCH OpenOCD
（`0.11.0+dev-snapshot`）+ WCH-LinkE（固件 v2.16），SDI 传输，扇区 1 KB。

## 结论

**这台 openocd 写 Flash 时会把整片 64 KB 擦掉**，不只是"镜像覆盖到的那几页"。实测三条：

| 命令 | 实测后果 |
|---|---|
| `program <elf> verify reset` | 镜像本身没问题（`Verified OK`），但 **`0x0800FC00` 那一页（位置/电机参数的存档页）变成全 `0xFF`** |
| `flash write_image <bin> 0x0000FC00` | **除写入范围以外的整片 Flash 全被擦掉**。实测：APP 区 52112 B 全变 `0xFF`，板子直接哑（串口无输出、PC 停在 0） |
| `flash write_image erase <bin> 0x0000FC00` | 同上，**加了 `erase` 也一样** |

> 第 2/3 条是"决定性的"：写之前 APP 是完整的，只跑这一条命令，写完 APP 区 0 个非 `0xFF` 字节。
> `dump_image` 是只读的，随便用，不会动 Flash。

## 正确做法：拼一整张 64 KB 镜像，一次 `program` 进去

```powershell
# 1) 生成 combined_app_params.bin = 主程序 + 0xFF 填充 + 最后 1 KB 参数页
python scripts/make_combined.py

# 2) 一次写完整颗芯片（注意路径用正斜杠，openocd 的 Tcl 会吃掉反斜杠）
& "c:/MounRiver/.../OpenOCD/OpenOCD/bin/openocd.exe" `
  -f debug/openocd.cfg -s "c:/MounRiver/.../OpenOCD/OpenOCD/bin" `
  -c "init" -c "halt" `
  -c "program E:/Codex/2026-10-06/l103-500rpm-stutter/work/combined_app_params.bin 0x00000000 verify reset" `
  -c "exit"
```

> **2026-10-06 第二次照此烧写成功**：`dump_image` 现取参数页（1024 B）→ `make_combined.py --params <那份 dump>` →
> 一次 `program combined_app_params.bin 0x00000000 verify reset` → `Verified OK`。烧后读回 `pp=11 / stall=3.00A /
> vbus=13.00V / home=-0.8630 rad` 全在，`pos_log` 序号 +1（正常轮转）。

`make_combined.py` 的参数：默认取 `build\L103_DRV8313_FOC.bin` + `work\flash_cfg_after_newpolicy.bin`
（那份最新的参数页 dump）；`--params` 可换。

## 参数页是什么、丢了会怎样

- 最后 1 KB（`0x0800FC00~0x0800FFFF`）= `pos_log` 的 4 页环状日志，
  32 B 一条，存：累计位置、sensor_offset、方向、对齐零点电角、机械零位、极对数、堵转阈值、母线电压。
- 丢了以后：上电**用编译默认值**（`board.h`），这台台子会变成 `pole_pairs = 14`（实际是 11）、
  没有机械零位、`aligned = 0`。FOC 方向/电角度全错，**不能直接发 `G`**。

## 参数页丢了怎么补救

**首选**：从备份写回（就是上面那张 combined 镜像）。备份放
`flash_cfg_*.bin`，
解码/查看用 `scripts\decode_poslog.py <file.bin>`。

**次选**（没有备份时，用串口重设一遍）：

```
#11,3.0,24     极对数 11 / 堵转 3.0 A / 母线 24 V   （存 Flash）
A              重新对齐（电机必须能自由转动）
F              把当前位置设为机械 0 点
```

注意 `A` 之后必须重设机械零位，且原来那个 0.0010 rad 的零点偏移**找不回来**。

## 另外两条容易踩的

- 烧写后 `reset run` 偶尔会失败（`unable to resume` / `dmstatus=0x00000c82`，
  表现为 `pc=0x00000000`、"Hart is not halted!" 交替出现）。**再跑一次
  `openocd -c "init" -c "reset run" -c "exit"` 一般就起来了**；实在不行拔插 WCH-LinkE。
- 用 `-c` 传路径给 openocd 时**必须用正斜杠**。用反斜杠会被 Tcl 吃掉，
  报 `couldn't open E:Codex6-10-06l103-...`（反斜杠连同后面的字符一起消失）。

## `dump_image` 之后**必须** `reset run`，否则板子停在 halt

`dump_image` 前面那一条 `-c "halt"` **不会自己解除**。只 `dump_image` + `exit` 的话，
CPU 停在调试器手里，表现是：**串口一个字符都不回**，而 openocd 还能正常连上。

（2026-10-06 踩到一次，误判成"串口不通 / 被 SSCOM 占用"。）

```powershell
& $ocd -f debug/openocd.cfg -s $sdir -c "init" -c "reset run" -c "exit"
```

## 参数页 dump 每次读都不一样 —— **多数情况是正常的**

> 2026-10-06 更正：这里**没有**单独的"参数页"，整个最后 1 KB
> （`0x0800FC00 ~ 0x0800FFFF`）**整片都是 `pos_log` 区**（见 `pos_log.h:20`、`pos_log.c:54`）——
> 4 页轮转、32 B 一条，**位置和参数都在同一条记录里**：
> `pos_rad / sensor_offset / sensor_direction / zero_electric_angle / home_off_rad / pole_pairs / stall_amp / vbus_v`。

程序每次上电会把**最旧的一页擦掉**再往里写记录，所以两次 `dump_image` 之间差几十~一百多字节
（`page0` 有时整页变 `0xFF`）都是正常的，**不代表参数丢了**。

**判参数有没有被破坏，不要比字节，要解码看字段值**：

```powershell
python scripts/decode_poslog.py <dump.bin>
```

末行给出最新那条记录，核对是不是：

```
最新: seq=... pos=... home=0.0010 rad  pp=11  stall=3.00A  vbus=24.00V
```

（2026-10-06 烧完 r6 后实测就是这一行，一字不差。）
